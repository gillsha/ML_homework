# Offline-результаты: raw-score ranking, popularity и paired bootstrap

Актуальный запуск: **2026-10-02 13:36:36 UTC**. Предыдущие Precision@10 **0,855% и
2,987% относятся к ошибочному ранжированию по обрезанной оценке**. Они не являются
результатами текущего рекомендателя. Ошибка устранена; качество CF не улучшилось,
а снизилось. Сравнение сохранено, результаты не подбирались под ожидаемый вывод.

## Воспроизведение и артефакты

Из `week3`, Node.js 18+:

```bash
node --test test.cjs
node evaluate.cjs --offline --output results
node verify-results.cjs
```

- `offline.json`: актуальный протокол (schemaVersion=2), параметры/окружение,
  SHA-256 исходников и данных, размеры/хеши split, кандидаты, когорты, метрики,
  равенства score, тайминги, bootstrap-интервалы.
- `offline-users.tsv` (**локальный, исключён из Git**): все 943 пользователя, relevant/test counts, top-10 ID,
  raw scores, clipped ratings, fallback, число соседей и метрики. Есть три актуальных
  метода и два `legacy_*` варианта. Для popularity поле рейтингов пустое: количество
  оценок не интерпретируется как рейтинг. Пустые Recall/NDCG — неопределённость, не 0.
- `clipped-reference.json`: сохранённый отчёт до исправления clipping. Его хеши кода
  исторические. Новый эксперимент на тех же кандидатах полностью воспроизвёл старые
  выдачи: хеши ID/оценок/fallback/соседей совпадают, не только агрегированные метрики.
- `verify-results.cjs`: независимо пересчитывает метрики и равенства из TSV,
  проверяет train-only popularity, порядок/кандидатов, пропуски метрик, split/когорты,
  хеши прогнозов, сопоставляет legacy с архивом и повторяет bootstrap по проверенным
  пользовательским метрикам.

В Git хранятся код, этот отчёт и компактные `offline.json` / `clipped-reference.json`.
Подробный TSV (~1,65 МБ) не публикуется. После клонирования сначала выполните
`node evaluate.cjs --offline --output results`, затем `node verify-results.cjs`.
Эксперимент восстановит TSV и обновит агрегированный JSON с локальными таймингами;
это не JSON диалога. PDF, окружения и экспорты диалога также исключены из публикации.

Повтор перезаписывает актуальные JSON/TSV, но не исторический reference. Для сравнения
отдельных процессов:

```bash
mkdir -p /tmp/hw3-offline-repeat
node evaluate.cjs --offline --output /tmp/hw3-offline-repeat
node verify-results.cjs results /tmp/hw3-offline-repeat
```

Время и timestamp вариативны; метрики, списки, bootstrap и хеши должны воспроизводиться
при одинаковом коде/данных. В TSV сохранились неокруглённые значения.

## Что исправлено в сортировке

Раньше `predict()` вычислял `score=clip(prediction,1,5)`, затем `recommend()` сортировал
по этому score. Разные прогнозы, например 5 и 6, становились равны, а их порядок
определял ID фильма. Это потеря ранжирующего сигнала, а не просто форматирование UI.

Теперь:

- `rawScore` — конечный исходный прогноз, ключ сортировки по убыванию;
- `score=clip(rawScore,1,5)` — только отображаемая оценка и значение для RMSE/MAE;
- точные равенства rawScore разрешаются по возрастанию movie ID;
- неконечные сходства не используются; NaN/Infinity итогового прогноза дают конечный
  fallback, не попадают в сортировку;
- старый clipped top-10 вычисляется дополнительно **по тому же полному набору
  уже оценённых кандидатов**, вне таймера актуальной выдачи.

### Равенства до/после на общей когорте 924 пользователей

Считаем точное равенство ключа сортировки, без округления для UI. «Соседние равенства»
— сумма `key[rank] == key[rank-1]` в top-10; всего возможно 924 × 9 = 8 316.
«Все пары» — сумма `m(m−1)/2` по группам одинаковых ключей внутри списка.

| Показатель | User: до | User: после | Item: до | Item: после |
|---|---:|---:|---:|---:|
| Пользователей с равенствами | 818 | 268 | 465 | 56 |
| Позиций в группах равных score | 6 221 | 678 | 2 487 | 126 |
| Соседних равенств | **5 351** | **351** | **2 004** | **67** |
| Всех равных пар | 23 882 | 376 | 7 701 | 75 |

Изменились состав или порядок top-10 у **704/924** пользователей user-based и
**365/924** item-based. Статистики всех 943 пользователей также есть в JSON.
У popularity равенства допустимы по целочисленному count: 455 соседних равенств
у основной когорты; tie-break тот же ID. Одинаковые показанные рейтинги 5/5 не
обязательно означают одинаковые raw scores и больше не определяют порядок.

## Протокол: без смены split, кандидатов и параметров

- Split seed **20261002**; `k=30`, `minCommon=3`, shrinkage=10, prior=10.
- Для каждого пользователя сортировка по hash(seed,user ID,movie ID), ties по movie ID.
  Test — `floor(20% × count)`, минимум одна при наличии двух оценок; одна минимум
  остаётся в train. Это не хронологическое разбиение.
- **80 367 train / 19 633 test**, 943 пользователя, 1 682 фильма каталога,
  1 651 фильм с train-оценками. Средние, сходства, соседи, fallback и popularity
  вычисляются только по train. Параметры по test не подбирались.
- Кандидаты для всех методов: **все фильмы с train-оценками минус train-история
  пользователя**, без negative sampling. В среднем 1 565,78 кандидата (1 061–1 635).
- Popularity = **число всех train-оценок фильма**, не средний рейтинг и не количество
  test/положительных оценок. По убыванию count, при равенстве — movie ID.
- Релевантность: **test rating >=4**. Ненаблюдавшиеся и test rating <4 не считаются
  попаданием. Это offline-допущение, а не доказательство отсутствия интереса.
- В test 33 оценки cold-start фильмов. 13 из них релевантны; они исключены из
  кандидатов, но **сохранены в знаменателях Recall/NDCG**. Cold-user test отсутствует.

## Отобранная когорта и точные знаменатели

Определим `R_u = {фильмы пользователя u в test с rating >=4}`. Основной фильтр:
**`|R_u| > 0`**, независимо от метода, кандидатов, найденных соседей или попаданий.

**До фильтра 943, исключены 19, после фильтра 924 пользователя.** Это отобранная
когорта с наблюдаемыми положительными test-объектами, не вся аудитория.

Исключены ID: **17, 51, 61, 155, 229, 302, 418, 461, 626, 635, 646, 685, 723, 726,
729, 797, 814, 822, 874**. У них test не пустой (4–7 оценок), но максимум не выше 3.
Точное число оценок/максимум каждого пользователя записаны в `cohort.excluded` JSON
и TSV; это не cold-start пользователи.

| Метрика | Знаменатель внутри пользователя | Агрегация |
|---|---|---|
| Precision@10 | 10; недостающие позиции — промах | Среднее по 924; эквивалентно hits / **9 240** |
| Recall@10 | **Индивидуальное `|R_u|`**, включая cold-фильмы | Среднее по 924; **не** total hits / 10 898 |
| NDCG@10 | `Σ 1/log2(rank+1)`, rank=1..min(10,`|R_u|`) | Среднее по 924 |
| HitRate@10 | Индикатор «есть хотя бы одно попадание» | Сумма индикаторов / **924** |
| MAE/RMSE | Ошибка по наблюдаемой test-паре | Все **19 633** пары, включая fallback |

Всего положительных test-пар **10 898**, но Recall здесь **macro**, не micro.
Для 19 пользователей без positives Recall и NDCG неопределены: JSON `null`, TSV
пустое поле. **Они не заменены нулями.** Precision=0/10 и HitRate=0 для них определены,
поэтому отдельно показаны эти две метрики по всей аудитории. Основная таблица всех
четырёх метрик использует одну общую отобранную когорту.

### Основная когорта: 924 пользователя

| Метрика | User-based (raw) | Item-based (raw) | Popularity (train count) |
|---|---:|---:|---:|
| Precision@10 ↑ | 0,000758 (**0,076%**) | 0,028680 (**2,868%**) | **0,128463 (12,846%)** |
| Recall@10 ↑ | 0,000570 | 0,019936 | **0,133819** |

| Попаданий / 9 240 позиций | 7 | 265 | **1 187** |

**Popularity лучше обоих CF по всем рассчитанным top-N метрикам.** Item-based

### Дополнительно: все 943 пользователя, без positive-test фильтра

| Определённая для всех метрика | User-based | Item-based | Popularity |
|---|---:|---:|---:|
| Precision@10 (hits / 9 430) | 0,0742% | 2,8102% | **12,5875%** |
| HitRate@10 (hit users / 943) | 0,7423% | 20,9968% | **61,7179%** |

Recall/NDCG «по всем 943» не выдаются как число: без дополнительного соглашения
они не определены. Вывод о превосходстве popularity не вызван только исключением 19.

### Что произошло с прежними результатами

| CF | Precision до (clipped) | Precision после (raw) | NDCG до → после |
|---|---:|---:|---:|
| User-based | 0,8550% | **0,0758%** | 0,011920 → 0,000746 |
| Item-based | 2,9870% | **2,8680%** | 0,026855 → 0,025174 |

Прежние **0,85% и 2,99% действительно зависели от ошибки ранжирования** и случайного
с точки зрения вкусов tie-break по ID. Исправление их не повысило: clipping фактически
улучшал измеренную выдачу относительно raw score, особенно user-based. Это не повод
вернуть ошибку. Новый результат показывает слабость самих score для retrieval;
их калибровку/подмешивание popularity по этому test не настраивали.

RMSE/MAE не изменились, поскольку продолжают оценивать clipped rating:
user **0,938595 / 0,731296**, item **0,924973 / 0,724777**. Bias-baseline рейтингов:
**0,955136 / 0,753014**. Он отличается от popularity; у count-baseline нет RMSE/MAE,
поскольку число оценок — не прогноз рейтинга. Хорошая RMSE не гарантирует top-N качество.

## Устойчивость: paired bootstrap

До расчёта зафиксированы **5 000** повторов, seed **20261003**, primary metric
**NDCG@10**, три контраста: item−user, popularity−user, popularity−item.
В каждом повторе выбираем с возвращением **924 пользовательских индекса**; одинаковые
индексы используются для всех методов и метрик. Усредняем парные разности, не
вычитаем независимо бутстрэпнутые средние. PRNG Mulberry32, percentile CI с линейной
интерполяцией квантилей; параметры и интервалы сохранены в JSON.

Для трёх primary сравнений — Bonferroni: **98,333% интервал на контраст** (номинальная
семья 95%). Обычные 95% интервалы остальных метрик в JSON — exploratory.

| Парная Δ NDCG@10 | Оценка Δ | 98,333% percentile CI |
|---|---:|---:|
| Item − User | +0,024429 | [+0,020143; +0,028971] |
| Popularity − User | +0,167441 | [+0,153326; +0,181778] |
| Popularity − Item | +0,143012 | [+0,128386; +0,158020] |

Ноль исключён во всех трёх скорректированных интервалах. Это поддерживает порядок
**popularity > item-based > user-based в условной пользовательской оценке данного
split и выбранной когорты**. Не заявляем универсальную значимость: bootstrap не
перестраивает модель, не учитывает вариативность train/test split или смену seed,
не заменяет временной/онлайн-тест. Percentile coverage и независимость пользовательских
единиц — предпосылки приближённой оценки, не гарантии.

## Проверки и оставшиеся ограничения

- 19 автоматических тестов: raw против clipped ranking, finite fallback при
  NaN/Infinity, tie-break, train-only popularity, парность/детерминизм bootstrap,
  null Recall/NDCG у zero-positive пользователей, прежние парсинг/ID/cold-start/leakage.
- Проверка TSV: все методы, legacy reference, сортировка, denominator/cohort,
  popularity counts, пересчёт метрик/равенств/хешей и bootstrap.
- Chromium: работа UI и отдельная регрессия «raw 6 выше raw 5, хотя оба показаны
  как 5/5»; старые проверки ошибок загрузки/Worker, мобильной ширины и ID сохранены.

Не устранялись искусственно: cold start, неполная и неслучайная наблюдаемость MovieLens,
нетемпоральный split, ограниченная масштабируемость, отсутствие diversity/novelty и
онлайн-проверки. Качество CF особенно слабое; изменён только корректный ranking и
добавлены контрольный baseline/оценка неопределённости, а не тюнинг под test.
